一、游戏概述

一句话：从一无所有开始，砍树挖矿发育 → 建大本营 → 造围墙+防御塔 → 出兵营出兵 → 带兵拆掉对方大本营，当上国王。

  • 俯视角 2D 非横版，自由地图
  • 手机优先 虚拟摇杆 + 按钮，PC 可玩
  • 单人 AI AI 完全镜像玩家逻辑
  • 小数值 伤害个位数、血量两位数，拒绝很多 0
  • Godot 4.7.2 禁用 4.4.x，显式类型声明（禁 :=）

3.7 AI 系统

核心原则

AI 完全镜像玩家逻辑：采集 → 建家 → 1塔 → 4墙 → 2兵营 → 攒铁升级 → 出兵进攻。

决策状态机

  • 每帧决定当前动作（采集/建造/升级/进攻）
  • 采集优先：资源不够时持续采集，攒够才回基地建（不会来回空转）
  • 严格建造顺序：塔 → 墙 → 兵营，按前置条件
  • 塔墙完工才建兵营：未完工则回基地等待
  • 建造失败冷却：找不到空地时采集 5 秒后重试

关键修复记录

⚠️ AI 来回空转 bug：早期 AI 资源不够时只采集 2.5 秒就冲回基地试建，不够又去采，反复切换。修复：改为「攒够才回基地建，不够就一直采」。

⚠️ AI 建不出兵营 bug：早期 AI 统计建筑数只算已完工，墙未完工时就冲去建兵营被拒→反复失败。修复：统计含建造中，且塔墙完工后才建兵营。

五、Godot 开发知识点

5.1 碰撞层与掩码（Collision Layer/Mask）

核心概念

  • collision_layer（碰撞层）：我「在」哪一层。用位掩码表示，可同时在多层。
  • collision_mask（碰撞掩码）：我「能撞到」哪些层。同样是位掩码。
  • 两个物体 A 和 B 能碰撞，当且仅当：A 的 layer 与 B 的 mask 有交集，且 B 的 layer 与 A 的 mask 有交集。

位运算速查

第1位 = 1 (2^0)
第2位 = 2 (2^1)
第3位 = 4 (2^2)
第4位 = 8 (2^3)
第5位 = 16 (2^4)
第6位 = 32 (2^5)
第7位 = 64 (2^6)

# 组合用加法或按位或
mask = 1 + 4 + 16 + 64   # = 85
mask = 1 | 4 | 16 | 64   # 同上

本项目的实战应用

围墙分阵营只挡敌方，就是通过给「我方墙」和「敌方墙」分配不同层（32/64），然后调整单位掩码实现的：

# 我方单位掩码 = 大本营(1) + 敌方单位(4) + 野怪(16) + 敌方围墙(64) = 85
# 不含我方围墙(32) → 我方单位不被自己墙挡
collision_mask = 85

# 敌方单位掩码 = 大本营(1) + 我方单位(2) + 野怪(16) + 我方围墙(32) = 51
# 不含敌方围墙(64) → 敌方单位不被自己墙挡
collision_mask = 51

常见坑

  • ⚠️ 忘记设置 mask → 物体不与任何东西碰撞（穿墙）
  • ⚠️ 两个同层物体 mask 都不含自己层 → 同队不碰撞（这是我们想要的）
  • ⚠️ Area2D 的 mask 决定它能「检测到」哪些层的 body
  • ⚠️ 资源不加碰撞体时，即使 layer 设了也没用（没有 CollisionShape2D）
5.2 状态机（State Machine）

应用场景

  • AI 决策：采集/建造/升级/进攻 四种状态，每帧切换
  • 建筑生命周期：建造中 → 已完工 → 升级中 → 拆除中 → 销毁
  • 小兵模式：驻守/跟随

简单状态机写法

# 用变量表示当前状态
var state: String = "idle"

func _process(delta: float) -> void:
    match state:
        "idle":
            _do_idle(delta)
        "gather":
            _do_gather(delta)
        "build":
            _do_build(delta)
        "attack":
            _do_attack(delta)

# 切换状态时做清理
func change_state(new_state: String) -> void:
    state = new_state
    match new_state:
        "gather": gather_target = null
        "build": build_timer = 0.0

本项目 AI 状态机的关键教训

⚠️ 状态切换太频繁 = 来回空转：早期 AI 在「采集」和「建造」之间每 2.5 秒切换一次，导致走到资源前又回基地。修复：资源不够时锁定在采集状态，攒够才切换到建造。

💡 原则：状态切换要有「足够的理由」，不要基于短计时器频繁切换。用「条件满足才切换」代替「定时切换」。

5.3 信号（Signal）与组（Group）

信号（Signal）

  • Godot 的观察者模式：一个节点发出信号，其他节点连接并响应
  • 内置信号：body_entered（Area2D 检测到物理体）、pressed（按钮点击）、tree_entered 等
  • 自定义信号：signal my_signal(arg1, arg2)
# 定义信号
signal destroyed(team: int, type: String)

# 发出信号
destroyed.emit(team, btype)

# 连接信号
body_entered.connect(_on_body_entered)
button.pressed.connect(func() -> void: print("clicked"))

组（Group）

  • 给节点打标签，方便批量查找和操作
  • add_to_group("building") 加入组
  • get_tree().get_nodes_in_group("building") 获取组内所有节点
# 本项目的组
"building"    # 所有建筑
"minion"      # 所有小兵
"wild"        # 所有野怪
"team0"       # 玩家方（玩家+小兵+建筑）
"team1"       # 敌方（AI+小兵+建筑）
"resource_node"  # 所有资源点
"projectile"  # 所有箭矢

实战技巧

  • 用组做阵营区分：is_in_group("team0") 判断敌我
  • 用组做批量遍历：找最近敌人时遍历 get_nodes_in_group("team1")
  • 注意：get_nodes_in_group 返回的是数组，遍历时如果节点可能被销毁，要先检查 is_instance_valid()
5.4 场景树与节点

核心概念

  • Godot 一切都是节点（Node），节点组成场景树
  • add_child(node) 添加子节点，remove_child(node) 移除
  • queue_free() 安全销毁节点（在当前帧结束后销毁，避免遍历中销毁导致崩溃）
  • get_tree() 获取场景树根，get_tree().current_scene 获取当前场景

动态创建节点

# 创建建筑
var b: Building = Building.new()
b.name = "Building_wall_001"
b.setup(self, team, type, pos)
add_child(b)

# 销毁（安全方式）
b.queue_free()

# 检查节点是否还有效（可能已被销毁）
if is_instance_valid(b):
    b.do_something()

常见坑

  • ⚠️ 遍历组时销毁节点 → 用 queue_free() 而不是 free()，且遍历前拷贝数组
  • ⚠️ 节点已销毁还访问其属性 → 用 is_instance_valid() 检查
  • ⚠️ get_node("path") 路径写错 → 优先用变量引用或 @onready
5.5 输入处理（鼠标/触摸）

三种输入方式

  1. _input(event)：全局输入，最先收到，适合放置/拆除等全局交互
  2. _unhandled_input(event)：未被 UI 消费的输入，适合游戏操作
  3. _gui_input(event)：Control 节点的输入，适合按钮/UI

鼠标事件

func _input(event: InputEvent) -> void:
    # 鼠标移动
    if event is InputEventMouseMotion:
        var mm: InputEventMouseMotion = event as InputEventMouseMotion
        print("鼠标位置: ", mm.position)

    # 鼠标按键
    elif event is InputEventMouseButton:
        var mb: InputEventMouseButton = event as InputEventMouseButton
        if mb.button_index == MOUSE_BUTTON_LEFT and mb.pressed:
            print("左键按下")

    # 触摸（手机）
    elif event is InputEventScreenTouch:
        var t: InputEventScreenTouch = event as InputEventScreenTouch
        if t.pressed:
            print("触摸位置: ", t.position)

    # 触摸拖动
    elif event is InputEventScreenDrag:
        var d: InputEventScreenDrag = event as InputEventScreenDrag
        print("拖动位置: ", d.position)

屏幕坐标 → 世界坐标

# CanvasLayer 中，屏幕坐标转世界坐标
func _screen_to_world(screen_pos: Vector2) -> Vector2:
    return get_viewport().get_canvas_transform().affine_inverse() * screen_pos

# Node2D 中可以直接用
var world_pos: Vector2 = get_global_mouse_position()

本项目放置模式的输入设计

  • 鼠标/手指移动 → 更新虚影位置（mouse_world）
  • 左键/触摸按下 → 检查是否点在 UI 按钮上，不是则放置/拆除
  • 放置模式下左半屏摇杆照常工作（_is_left_zone 判断）

CanvasLayer

  • 独立于游戏世界的渲染层，UI 不随相机移动
  • extends CanvasLayer，所有子节点都在屏幕空间
  • 本项目 HUD 就是一个 CanvasLayer，包含资源条、计时、建造按钮、摇杆等

5.7 _draw 自定义绘制

核心方法

  • _draw()：Node2D 的虚函数，每帧重绘时调用
  • queue_redraw()：请求重绘（在下一帧调用 _draw）
  • 常用绘制函数：draw_rect、draw_circle、draw_line、draw_string、draw_colored_polygon

本项目的 _draw 应用

# 绘制建筑（色块 + 边框）
func _draw() -> void:
    draw_rect(Rect2(-half, -half, half*2, half*2), color)
    draw_rect(Rect2(-half, -half, half*2, half*2), Color(0,0,0,0.5), false, 2.0)

# 绘制虚线圆（范围圈）
func _draw_dashed_circle(pos, r, col, width, dash, gap):
    var a: float = 0.0
    while a < TAU:
        var a1: float = minf(a + dash, TAU)
        var p0: Vector2 = pos + Vector2(cos(a), sin(a)) * r
        var p1: Vector2 = pos + Vector2(cos(a1), sin(a1)) * r
        draw_line(p0, p1, col, width)
        a += dash + gap

# 绘制文字标签
var font: Font = ThemeDB.fallback_font
draw_string(font, Vector2(-24, 8), "大", HORIZONTAL_ALIGNMENT_CENTER, 48, 18, Color.WHITE)

注意事项

  • ⚠️ _draw 只在节点可见时调用，且只绘制一次（需要持续更新就每帧 queue_redraw）
  • ⚠️ 绘制坐标是节点的局部坐标，不是全局坐标
  • ⚠️ draw_string 的字体要用 ThemeDB.fallback_font，否则可能不显示
5.8 CharacterBody2D 移动

基本移动

extends CharacterBody2D

var speed: float = 300.0
var velocity: Vector2 = Vector2.ZERO

func _physics_process(delta: float) -> void:
    # 获取输入
    var input_dir: Vector2 = Vector2(
        Input.get_axis("move_left", "move_right"),
        Input.get_axis("move_up", "move_down")
    ).normalized()

    # 设置速度
    velocity = input_dir * speed

    # 移动并处理碰撞
    move_and_slide()

本项目的移动方式

  • 玩家/AI/小兵/野怪都用 CharacterBody2D
  • 手机端用虚拟摇杆：external_move 变量接收摇杆输入（-1~1）
  • AI/小兵用 _move_to(target_pos)：朝目标点移动，自动处理碰撞
func _move_to(target: Vector2) -> void:
    var dir: Vector2 = (target - global_position).normalized()
    velocity = dir * speed
    move_and_slide()

# 手机摇杆输入
var external_move: Vector2 = Vector2.ZERO  # 由 HUD 摇杆设置

func _physics_process(delta: float) -> void:
    velocity = external_move * speed
    move_and_slide()

击退实现

var knockback: Vector2 = Vector2.ZERO

func _physics_process(delta: float) -> void:
    # 击退衰减
    knockback = knockback.move_toward(Vector2.ZERO, 700.0 * delta)
    # 正常移动 + 击退
    velocity = external_move * speed + knockback
    move_and_slide()

# 受到击退
func _apply_knockback(dir: Vector2, strength: float) -> void:
    knockback = dir.normalized() * strength
5.9 Area2D 检测

Area2D vs CharacterBody2D

  • CharacterBody2D：有物理碰撞，会被挡住，适合玩家/敌人/建筑
  • Area2D：无物理碰撞，只做检测，适合箭矢/掉落物/触发区域

箭矢（Area2D）

extends Area2D

func _ready() -> void:
    body_entered.connect(_on_body_entered)

func _on_body_entered(body: Node) -> void:
    # 检查命中的是不是敌人
    if body.is_in_group("team1") and body.has_method("take_damage"):
        body.take_damage(damage, team)
        queue_free()  # 箭消失

func _physics_process(delta: float) -> void:
    # 箭飞行
    global_position += direction * speed * delta

掉落物（Area2D）

extends Area2D

func _ready() -> void:
    body_entered.connect(_on_body_entered)
    # 掩码设为玩家层(2)+敌层(4)，只检测单位
    collision_mask = 6

func _on_body_entered(body: Node) -> void:
    if body is Player or body is Minion:
        # 拾取资源
        collect()
        queue_free()

关键：mask 决定检测范围

💡 Area2D 的 collision_mask 决定它能检测到哪些层的 body。箭矢 mask 设为敌方单位层+建筑层+野怪层，就能命中这些目标。

6.2 核心类关系
  • GameManager（game.gd）：总控，持有所有引用（player/ai_hero/hud/preview/基地），管理资源/建造/出兵/胜负
  • Player / AiHero：继承 CharacterBody2D，各自实现移动/攻击逻辑
  • Building：继承 StaticBody2D，统一处理所有建筑类型（用 btype 区分）
  • Minion：继承 CharacterBody2D，小兵行为
  • WildMonster：继承 CharacterBody2D，野怪行为
  • Hud：继承 CanvasLayer，所有 UI
  • BuildPreview：继承 Node2D，放置虚影

通信方式

  • GameManager → 其他：直接调用方法（game.player.attack()）
  • 其他 → GameManager：通过 game 引用调用（game.try_build()）
  • 建筑 → GameManager：信号（game.on_building_finished(b)）
  • UI → GameManager：按钮回调（Callable(game, "try_build")）

七、调试与踩坑经验

7.1 AI 来回空转（最经典的 bug）

症状

AI 收集远处资源时，走到资源前 → 回大本营 → 又走到资源前 → 又回大本营，永远采不到资源。

根因

AI 决策状态机在「采集」和「建造」之间频繁切换：资源不够时只采集 2.5 秒就冲回基地试建，不够又去采。地图大、资源远，每次往返路程很长，采一两下就被打断。

修复

改为「攒够才回基地建，不够就一直采」：资源不够时锁定在采集状态，直到攒够建造所需资源才切换到建造状态。

教训

💡 状态切换要有「足够的理由」，不要基于短计时器频繁切换。用「条件满足才切换」代替「定时切换」。

7.2 AI 建不出兵营

症状

AI 建了塔和墙，但一直建不出兵营。

根因

  1. AI 统计建筑数只算「已完工」，建造中的墙/塔没被统计 → 反复刷同类建筑
  2. 兵营前置要求「已完工的 4 墙+1 塔」，但 AI 在墙未完工时就冲去建兵营 → 被游戏拒绝 → 反复失败空转

修复

  • 统计建筑数含「建造中」的总数，避免重复建同类
  • 塔墙均完工后才建兵营，未完工则回基地等待
  • 建造失败进 5 秒重试冷却
7.3 碰撞体系重做

问题

  • 资源有碰撞体 → 卡住 AI/玩家行动
  • 小兵同队碰撞 → 自己人堵路
  • 围墙双方都挡 → 自己人回不了家

解决方案

重新分配碰撞层，给围墙分阵营（我方墙=层32，敌方墙=层64），调整各单位掩码：

  • 资源移除碰撞体
  • 同队单位掩码不含自己层 → 同队不碰撞
  • 我方单位掩码含敌方墙(64)不含我方墙(32) → 过自己墙、挡敌人墙

教训

💡 碰撞层/掩码是 Godot 2D 游戏最核心的机制之一，设计前先画好层位表，避免后期大改。

7.4 弓箭穿模（命中检测失败）

症状

弓箭直接穿过敌人，不造成伤害。

可能原因

  • 箭矢的 collision_mask 不含敌人所在层
  • 敌人没有 take_damage 方法或不在对应组
  • 箭矢速度太快，一帧穿过敌人（隧道效应）

排查方法

  1. 打印箭矢的 mask 和命中的 body 信息
  2. 确认敌人的 collision_layer 是否在箭矢 mask 范围内
  3. 确认 body_entered 信号是否连接
7.5 血条显示 bug

症状

  • 野怪受攻击后血条不显示/显示后消失
  • 敌方单位血条不显示

修复

  • 血条在 take_damage 时更新并显示
  • 复活时也更新血条显示
  • 敌方英雄/小兵血条设为常显（always_show = true）
  • 大本营血条常显，其他单位受攻击才显示
7.6 验证工作流

本项目的验证流程

  1. 暂存工程：在 staging_king 改代码（不影响真实工程）
  2. headless import：godot --path staging --headless --import 检查脚本错误
  3. 冒烟测试：smoke_test.gd 自动运行 45 秒，写入 smoke_result.txt（断言 SMOKE_OK）
  4. 同步真实工程：Copy-Item 把改好的脚本同步到 E:\GodotProjects\我要当国王
  5. 真实工程 import：再次 headless import
  6. 启动 GUI：Start-Process 启动游戏窗口，记录 PID
